# Homework (Simulación) — La Abstracción del Proceso

Este programa, [`process-run.py`](process-run.py), permite observar cómo cambian los estados de los procesos a medida que los programas se ejecutan y ya sea utilizan la CPU (por ejemplo, realizando una instrucción de suma) o realizan I/O (por ejemplo, enviando una solicitud a un disco y esperando a que se complete). Vea el [README](https://github.com/remzi-arpacidusseau/ostep-homework/blob/master/cpu-intro/README.md) para más detalles.

## Preguntas

1. Ejecute `process-run.py` con las siguientes banderas: `-l 5:100,5:100`. ¿Cuál debería ser la utilización de CPU (por ejemplo, el porcentaje de tiempo en que la CPU está en uso)? ¿Por qué sabe esto? Use las banderas `-c` y `-p` para ver si tenía razón.
2. Ahora ejecute con estas banderas: `./process-run.py -l 4:100,1:0`. Estas banderas especifican un proceso con 4 instrucciones (todas para usar la CPU), y uno que simplemente emite una I/O y espera a que se complete. ¿Cuánto tiempo toma completar ambos procesos? Use `-c` y `-p` para averiguar si tenía razón.
3. Cambie el orden de los procesos: `-l 1:0,4:100`. ¿Qué sucede ahora? ¿Importa cambiar el orden? ¿Por qué? (Como siempre, use `-c` y `-p` para ver si tenía razón)
4. Ahora exploraremos algunas de las otras banderas. Una bandera importante es `-S`, la cual determina cómo reacciona el sistema cuando un proceso emite una I/O. Con la bandera configurada en SWITCH_ON_END, el sistema NO cambiará a otro proceso mientras uno está haciendo I/O, sino que esperará hasta que el proceso esté completamente terminado. ¿Qué sucede cuando ejecuta los siguientes dos procesos (`-l 1:0,4:100 -c -S SWITCH_ON_END`), uno haciendo I/O y el otro haciendo trabajo de CPU?
5. Ahora, ejecute los mismos procesos, pero con el comportamiento de cambio configurado para cambiar a otro proceso cada vez que uno está ESPERANDO por I/O (`-l 1:0,4:100 -c -S SWITCH_ON_IO`). ¿Qué sucede ahora? Use `-c` y `-p` para confirmar que tiene razón.
6. Otro comportamiento importante es qué hacer cuando una I/O se completa. Con `-I IO_RUN_LATER`, cuando una I/O se completa, el proceso que la emitió no necesariamente se ejecuta de inmediato; más bien, lo que sea que estuviera ejecutándose en ese momento sigue ejecutándose. ¿Qué sucede cuando ejecuta esta combinación de procesos? (`./process-run.py -l 3:0,5:100,5:100,5:100 -S SWITCH_ON_IO -c -p -I IO_RUN_LATER`) ¿Se están utilizando efectivamente los recursos del sistema?
7. Ahora ejecute los mismos procesos, pero con `-I IO_RUN_IMMEDIATE` configurado, lo cual ejecuta inmediatamente el proceso que emitió la I/O. ¿En qué difiere este comportamiento? ¿Por qué podría ser una buena idea ejecutar de nuevo inmediatamente un proceso que acaba de completar una I/O?
8. Ahora ejecute con algunos procesos generados aleatoriamente usando las banderas `-s 1 -l 3:50,3:50` o `-s 2 -l 3:50,3:50 o -s 3 -l 3:50,3:50`. Vea si puede predecir cómo resultará la traza. ¿Qué sucede cuando usa la bandera `-I IO_RUN_IMMEDIATE` versus la bandera `-I IO_RUN_LATER`? ¿Qué sucede cuando usa la bandera `-S SWITCH_ON_IO` versus `-S SWITCH_ON_END`?
